Make a LoRA

A LoRA is a small add-on file that teaches FLUX.2 klein one thing it does not know: a style, a character, an object. You make it from your own pictures, with mflux's trainer, mflux-train, on this Mac. HikariLM does not train; this page walks you through doing it in Terminal, with every command to copy. HikariLM draws with LoRAs on FLUX.2 klein base 4B.

Before you start. Set up making pictures first (the picture setup page), so mflux is installed in ~/.hikarilm/pictures-venv. Training takes hours and uses the whole Mac, so stop HikariLM while it runs (hikarilm stop) and start it again after (hikarilm start). The commands below use a folder for each LoRA, such as ~/lora/zq-usagi; make it and go into it first:

mkdir -p ~/lora/zq-usagi/dataset && cd ~/lora/zq-usagi

1 LoRA or QLoRA: pick the base and download it

LoRAs are trained on the base model, not the quick 4-step one. The LoRA itself is always the same small file; what differs is how the 4B it learns on is held in memory while it trains:

  • QLoRA: the base model is quantized (4-bit) and stays frozen; only the LoRA, kept in full precision, learns. It needs the least memory and the smallest download. Start here.
  • LoRA: the base model in 8-bit or in full precision. It needs more memory and time, and keeps a little more of the base model's detail while it learns.

The 4-bit copy:

~/.hikarilm/venv/bin/hf download mflux-community/flux-2-klein-base-4b-mflux-q4

or the 8-bit one, or the full one:

~/.hikarilm/venv/bin/hf download mflux-community/flux-2-klein-base-4b-mflux-q8
~/.hikarilm/venv/bin/hf download black-forest-labs/FLUX.2-klein-base-4B

A LoRA made on any of them draws on all of them, so you can train on one and draw in HikariLM with the 4-bit one. If a run is killed at its first step for want of memory, go one row up, and see gradient_checkpointing and low_ram in step 5.

2 Gather the pictures

Put them in dataset/, each with a caption file of the same name:

zq-usagi/
  dataset/
    001.png
    001.txt
    002.jpg
    002.txt
    …
    preview_1.txt
  train.json
  • PNG, JPEG or WebP. Any size; the long side is brought down to max_resolution (1024). The names do not matter, only that a picture and its .txt share one.
  • How many: for a character or an object, 15 to 40; for a style, 30 to 80. Variety teaches more than numbers: the thing you want, in different poses, places, lights and framings. Leave out blurry pictures, near-copies, and pictures where the thing is tiny or cut off. Crop each so the thing fills a good part of it.
  • Nothing in them you do not want learned: watermarks, text, frames, the same background in every one. What is in every picture ends up in the LoRA.
  • preview_1.txt, preview_2.txt… (optional) are prompts it draws every so often while it trains, so you can see the LoRA take hold. Write them the way you will prompt later (step 3), such as zq_usagi, riding a bicycle by the sea. Pick something that is in none of your pictures, so you can see whether it learned the character or just copies the pictures.

Every picture needs its .txt; the trainer stops and names one that has none. This lists any that are missing one:

find dataset -type f \( -iname '*.png' -o -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.webp' \) | while read -r f; do [ -f "${f%.*}.txt" ] || echo "No caption: $f"; done

3 Write the captions

The captions decide what the LoRA learns, more than anything else on this page.

A trigger word, or none

A trigger word is a name you make up for the thing the LoRA learns, such as zq_usagi. It goes at the start of every caption, and later in a prompt where you want the LoRA to show. While training, the model sees the word next to your pictures again and again, and comes to read it as "this character" or "this style".

Not every LoRA needs one. Without one, the LoRA shows in every picture drawn with it loaded, as much as its strength says, which is often what a style LoRA is for. With one, it shows when the prompt has the word, so you can call it up in some pictures and not others. Use one for a character or an object you want to name in a prompt, or when the thing has a name the model already knows something else by. In HikariLM, leave the LoRA's trigger word empty if it has none.

If you use one, it must be a word the model has never seen, such as zq_usagi or zq_style. A real word already means something: train on rabbit and you blur your character with every rabbit the model knows, and every rabbit you draw afterwards turns into yours. Keep it short, with no spaces, and the same in every caption.

Sentences or tags

FLUX.2 klein reads plain sentences, so caption in sentences, the way you will prompt: sitting on a park bench, holding a red umbrella, rainy evening. If you would rather prompt in booru tags (1girl, solo, white_hair, rabbit_ears, park_bench, umbrella, rain), caption every picture in tags instead, and keep to it: a LoRA learns the kind of words it was trained on. In HikariLM, turn on Prompt with tags for such a LoRA.

Optional: if you want to keep writing sentences and have them turned into tags, a model that does that, such as BooruNL, can do it, both for captions and in HikariLM (Settings, Make tags with). Nobody needs one; you can write the tags yourself. One converted to MLX goes in ~/.hikarilm/models; BooruNL, for example, is converted with mlx-vlm:

~/.hikarilm/venv/bin/mlx_vlm.convert --hf-path cooperdk/BooruNL-0.8B -q --q-bits 8 --mlx-path ~/.hikarilm/models/BooruNL-0.8B-8bit

Describe what changes, leave out what the LoRA should learn

For every picture, the model tries to explain what it sees with the caption. What the caption names, it puts down to those words. What the caption never names, but is in every picture, it puts down to what is in every caption (the trigger word, if there is one) and to the LoRA itself. So:

  • Describe what is different in each picture: the pose, the place, the clothes that change, the light, the framing. Those stay yours to choose in a prompt.
  • Leave out what is the same in every picture and is what you want: a character's face, fur and colors, or a style's brushwork and palette. That is what the LoRA learns.

Example: a character, with a trigger word. Thirty pictures of Usagi, a white rabbit girl with long ears tipped pink, red eyes and a blue scarf. Trigger word zq_usagi.

The pictureCaption
Usagi on a park bench in the rain, with an umbrellazq_usagi, sitting on a park bench, holding a red umbrella, rainy evening, side view
Usagi waving in a kitchenzq_usagi, standing in a kitchen, waving, smiling, morning light, close-up
Usagi asleep under a treezq_usagi, asleep under a cherry tree, petals falling, wide shot

None of them says white fur, pink-tipped ears, red eyes or rabbit girl: those are in every picture and are what zq_usagi should mean. Afterwards, zq_usagi, riding a bicycle by the sea draws her with all of it, without saying any of it.

Not: zq_usagi, a white rabbit girl with long pink-tipped ears, red eyes and a blue scarf, sitting on a bench. The caption explains her look, so the trigger word learns little, and she only comes out when you spell all of it out again.

The scarf is your choice. Leave it out of every caption and it becomes part of her: she always wears it. Name it (wearing a blue scarf) in the pictures where she has it, and it stays something you can ask for or leave out. Do the same for anything that should stay optional.

Example: a style, with no trigger word. Forty paintings with soft watercolor edges and a muted teal-and-orange palette.

The pictureCaption
A lighthouse at sunseta lighthouse on a cliff at sunset, waves below
A cat on a windowsilla cat sleeping on a windowsill, potted plants

Say what is in the picture, never how it is painted: no "watercolor", "soft edges" or "teal". With the LoRA loaded, a busy train station comes out in that style, more or less as its strength says. Want to switch it on per prompt instead? Start every caption with zq_style, and prompt with it.

Example: the same character, captioned in tags.

The pictureCaption
Usagi on a park bench in the rainzq_usagi, solo, sitting, bench, park, holding_umbrella, red_umbrella, rain, evening, from_side
Usagi waving in a kitchenzq_usagi, solo, standing, kitchen, waving, smile, morning, close-up

The same rule: no white_hair, rabbit_ears, red_eyes. Prompt later in tags too.

Drafts for every picture, with a model that can see

Writing thirty captions by hand is slow; a vision model can draft them, and you fix each one after. Save this as make_captions.py in the LoRA's folder. It uses Gemma 3 12B (the model HikariLM reads pictures with) from ~/.hikarilm/venv, writes a .txt beside every picture that has none, and never changes one that is there:

"""Draft a caption for every picture in a folder that has none yet.

    ~/.hikarilm/venv/bin/python make_captions.py dataset --trigger zq_usagi \
        --leave-out "white fur, long pink-tipped ears, red eyes, rabbit girl"
"""
import argparse
from pathlib import Path

from mlx_vlm import apply_chat_template, generate, load
from mlx_vlm.utils import load_config

parser = argparse.ArgumentParser()
parser.add_argument("folder")
parser.add_argument("--model", default="mlx-community/gemma-3-12b-it-4bit")
parser.add_argument("--trigger", default="", help="put in front of every caption; none if empty")
parser.add_argument("--leave-out", default="", help="what the LoRA should learn, never to be named")
parser.add_argument("--tags", action="store_true", help="booru tags instead of sentences")
args = parser.parse_args()

ask = ("Describe this picture for a caption: the pose, what the subject is doing and holding, the place, "
       "the light and the framing, in one short line of comma-separated phrases, no full sentences.")
if args.tags:
    ask = "List danbooru tags for this picture: pose, action, objects, place, light, framing. Comma-separated, nothing else."
if args.leave_out:
    ask += f" Never mention any of these, not even in other words: {args.leave_out}."
ask += " Do not name the art style."

model, processor = load(args.model)
config = load_config(args.model)
pictures = sorted(p for p in Path(args.folder).iterdir() if p.suffix.lower() in (".png", ".jpg", ".jpeg", ".webp"))
for picture in pictures:
    caption_file = picture.with_suffix(".txt")
    if caption_file.exists():
        continue
    prompt = apply_chat_template(processor, config, ask, num_images=1)
    text = generate(model, processor, prompt, [str(picture)], max_tokens=120, temperature=0.0, verbose=False).text
    text = " ".join(text.strip().strip('"').split())
    caption = f"{args.trigger}, {text}" if args.trigger else text
    caption_file.write_text(caption + "\n", encoding="utf-8")
    print(f"{picture.name}: {caption}")

Run it, with the look of what the LoRA should learn after --leave-out (and --tags for tag captions, or no --trigger for none):

~/.hikarilm/venv/bin/python make_captions.py dataset --trigger zq_usagi --leave-out "white fur, long pink-tipped ears, red eyes, rabbit girl"

Then read every caption next to its picture and fix it: the model still names some of what it was told to leave out, and gets details wrong. HikariLM stays stopped while it runs; it loads the model itself.

4 Write preview prompts

One prompt per file, in dataset/, written like your captions, of things in none of your pictures:

echo "zq_usagi, riding a bicycle along a seaside road, golden hour, wide shot" > dataset/preview_1.txt
echo "zq_usagi, reading a book in a library, rainy day, close-up" > dataset/preview_2.txt

For a LoRA with no trigger word, leave the word out: a busy train station at night.

5 Write train.json

Save this as train.json in the LoRA's folder, beside dataset/. data is read from where train.json is; an absolute path such as /Users/you/lora/zq-usagi/dataset works too. As it stands it makes a QLoRA on the 4-bit base; for the others, change model_path and quantize as in step 1.

{
  "model": "flux2-klein-base-4b",
  "model_path": "mflux-community/flux-2-klein-base-4b-mflux-q4",
  "data": "dataset/",
  "seed": 42,
  "steps": 50,
  "guidance": 4.0,
  "quantize": null,
  "max_resolution": 1024,
  "low_ram": false,
  "gradient_checkpointing": true,
  "training_loop": { "num_epochs": 20, "batch_size": 1 },
  "optimizer": { "name": "AdamW", "learning_rate": 1e-4 },
  "checkpoint": { "output_path": "training", "save_frequency": 200 },
  "monitoring": {
    "preview_width": 768,
    "preview_height": 768,
    "plot_frequency": 50,
    "generate_image_frequency": 200
  },
  "lora_layers": {
    "targets": [
      { "module_path": "transformer_blocks.{block}.attn.to_q", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.attn.to_k", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.attn.to_v", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.attn.to_out", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.attn.add_q_proj", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.attn.add_k_proj", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.attn.add_v_proj", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.attn.to_add_out", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.ff.linear_in", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.ff.linear_out", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.ff_context.linear_in", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "transformer_blocks.{block}.ff_context.linear_out", "blocks": { "start": 0, "end": 5 }, "rank": 16 },
      { "module_path": "single_transformer_blocks.{block}.attn.to_qkv_mlp_proj", "blocks": { "start": 0, "end": 20 }, "rank": 16 },
      { "module_path": "single_transformer_blocks.{block}.attn.to_out", "blocks": { "start": 0, "end": 20 }, "rank": 16 }
    ]
  }
}

What to change, if anything:

  • model_path and quantize: LoRA or QLoRA, as in step 1.
  • num_epochs: how many times it goes through every picture. A step is one picture, so 30 pictures for 20 epochs are 600 steps, and 100 pictures for 20 epochs are 2,000. Fewer pictures, more epochs: aim for about 1,000 to 2,000 steps.
  • save_frequency and generate_image_frequency: every how many steps it saves a checkpoint and draws the previews. Keep them the same, so every checkpoint has previews to judge it by; with few steps in all, make them smaller (100).
  • learning_rate: how big each step is. Lower it (5e-5) if the previews go wrong early.
  • rank: how much the LoRA can hold. 16 is plenty for one style or character; 32 for more, at twice the file size. Each target can also take "alpha", which scales the LoRA by alpha ÷ rank while it learns (as in published recipes); left out, it is 1.
  • gradient_checkpointing: on, it needs far less memory and steps take about 30% longer. Turn it off only on a Mac with memory to spare. low_ram: on, for the tightest Macs, slower still.
  • steps and guidance: how the previews are drawn (the base 4B's 50 steps, guidance 4), not how it learns.
  • The lora_layers cover every block of the 4B (5 and 20). Leave them.

6 Check, then train

In Terminal, in the LoRA's folder. First a check that reads the config and the pictures without loading the model:

~/.hikarilm/pictures-venv/bin/mflux-train --config train.json --dry-run

When it says Training config validated, train. caffeinate -i keeps the Mac from sleeping while it runs:

caffeinate -i ~/.hikarilm/pictures-venv/bin/mflux-train --config train.json

Keep the Terminal window open; it shows the steps as they go. If it stops (you closed it, the Mac restarted), go on from the last checkpoint instead of starting over; dataset/ must still be where it was:

caffeinate -i ~/.hikarilm/pictures-venv/bin/mflux-train --resume "$(ls training*/checkpoints/*_checkpoint.zip | tail -1)"

If mflux-train is not found, or does not know flux2-klein-base-4b, update mflux: ~/.hikarilm/pictures-venv/bin/pip install -U mflux.

7 Watch it

Everything goes into training/ (or training_ and the date, if that folder is already there):

  • training/preview/: the preview pictures, by step. This is what to judge by. open training/preview shows them in Finder.
  • training/loss/loss.html: the loss chart; open training/loss/loss.html. It falls, then flattens.
  • training/checkpoints/: a checkpoint every save_frequency steps, such as 0000600_checkpoint.zip.

Early previews look like the plain model. Then the LoRA starts to show. Past the best point, the previews copy your training pictures, lose what the prompt asks for, or turn harsh and oversaturated: that is overtraining. The best checkpoint is often not the last one. Note the step of the previews you like best; you can stop training there with Ctrl+C.

8 Take the LoRA out of the training

A checkpoint zip holds the LoRA as …_adapter.safetensors, beside the optimizer and what the trainer needs to go on. See what is in one:

unzip -l training/checkpoints/0001400_checkpoint.zip

Take the LoRA out of the one you picked, and give it a name you will know:

unzip -j training/checkpoints/0001400_checkpoint.zip '*_adapter.safetensors' && mv 0001400_adapter.safetensors zq-usagi.safetensors

Not sure which is best? Take every checkpoint's LoRA out into loras/:

mkdir -p loras && for z in training*/checkpoints/*_checkpoint.zip; do unzip -o -j -q "$z" '*_adapter.safetensors' -d loras; done && ls loras

and draw the same prompt and seed with each, to compare side by side:

for f in loras/*_adapter.safetensors; do ~/.hikarilm/pictures-venv/bin/mflux-generate-flux2 --model mflux-community/flux-2-klein-base-4b-mflux-q4 --steps 50 --guidance 4 --seed 1 --prompt "zq_usagi, reading a book in a library, rainy day, close-up" --lora "$f" 1.0 --output "try-$(basename "$f" _adapter.safetensors).png"; done && open try-*.png

The file is all you need from the training. Keep dataset/ and train.json in case you want to train it again.

9 Try it

Draw with it at full strength (the 1.0 after its name):

~/.hikarilm/pictures-venv/bin/mflux-generate-flux2 --model mflux-community/flux-2-klein-base-4b-mflux-q4 --steps 50 --guidance 4 --seed 1 --prompt "zq_usagi, riding a bicycle along a seaside road, her scarf blowing in the wind, golden hour, wide shot" --lora zq-usagi.safetensors 1.0 --output try.png

Prompting with it. Write the prompt the way you wrote the captions: the trigger word first (if it has one), then only what this picture should have.

PromptWhat comes out
zq_usagi, riding a bicycle along a seaside road, her scarf blowing in the wind, golden hour, wide shotUsagi, with her white fur, pink-tipped ears and red eyes, though the prompt says none of it, on a bicycle by the sea in evening light.
zq_usagi, reading a book in a library, sitting by the window, rainy day, close-upThe same Usagi, somewhere she never was in your pictures. That is the test that it learned her rather than your pictures.
zq_usagi, wearing a red raincoat instead of her scarf, jumping in puddlesUsagi in a raincoat, if the scarf was named in the captions (step 3). If it never was, it is part of her, and she may keep it on anyway.
a white rabbit girl riding a bicycle by the seaA rabbit girl who may look a little like Usagi, but not reliably: a loaded LoRA leans on every picture somewhat, but it is the trigger word that calls her up.
  • Do not describe what the LoRA learned in the prompt; it already knows it, and spelling it out can pull it toward the model's own idea of those words.
  • A trigger word only works with the LoRA loaded (--lora). Without it, zq_usagi is a word the model has never seen and means nothing to it.
  • Too strong (stiff poses, the same face and framing every time, colors burnt) or too weak (it looks off)? Change the 1.0 after the file name: 0.7 for less, 1.2 for more. Strength is chosen when you draw, so the file stays as it is.

10 Draw with it in HikariLM

Upload the .safetensors file to a Hugging Face repo of your own, then add it in Settings, under LoRAs, by its repo name, and pick it under Options when drawing with FLUX.2 klein base 4B. Adding the file straight from this Mac comes in HikariLM 6.0.

  • Trigger word: type it for the LoRA in Settings, and HikariLM puts it in front of your prompt, so riding a bicycle along a seaside road is enough. Leave it empty for a LoRA that has none.
  • Prompt with tags: turn it on for a LoRA captioned in tags. Then Make tags, by Options, turns your sentence into tags with the model under Settings, Make tags with, if you have one; or write the tags yourself.
  • HikariLM draws a LoRA picture the way step 9 does, with mflux-generate-flux2, so what you saw there is what you get.
